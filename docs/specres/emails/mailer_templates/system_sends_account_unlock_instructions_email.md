## Functional Overview

When a user's account has been locked due to too many failed sign-in attempts, the system sends an account unlock instructions email. The email is delivered via `DeviseMailer`, which inherits Devise's default `unlock_instructions` action without overriding it. Before the action runs, two before-actions configure the SMTP sender address and subject using community settings, and resolve the subforem context so that URLs in the email point to the correct subforem domain. The email body greets the user by email address, explains that the account was locked, and provides a one-time unlock link.

## Design Intent

Devise's built-in lockable module handles the unlock token lifecycle. `DeviseMailer` deliberately does not override `unlock_instructions` because no custom subject or body logic is needed beyond what the shared before-actions already provide. Click tracking (Ahoy) is disabled on all `DeviseMailer` actions by overriding `save_ahoy_options` with a no-op, preventing security-sensitive emails from being flagged as spam by mail filters.

## Key Members

- `@resource` — the locked Devise user record; provides `@resource.email` used in the template greeting
- `@token` — the one-time unlock token generated by Devise's lockable module; embedded in the unlock URL
- `@subforem_domain` — the resolved host used to build the unlock URL, derived from the user's `onboarding_subforem_id` or the default subforem domain
- `unlock_url(@resource, unlock_token: @token)` — the full unlock link rendered in the email template

## Scenarios

### Account is locked and unlock email is triggered

1. Devise's lockable strategy detects that the user has exceeded the maximum number of failed sign-in attempts and locks the account.
2. Devise calls `DeviseMailer#unlock_instructions`, which triggers the before-actions.
3. The `use_settings_general_values` before-action sets the sender address to the community name and configured `from` address, and sets the URL host to `Settings::General.app_domain`.
4. The `setup_subforem_context` before-action looks up the user's subforem via `onboarding_subforem_id` (falling back to the default subforem), resolves the corresponding domain, and updates the URL host accordingly.
5. Devise's default action assigns `@resource` and generates `@token`, then renders the `unlock_instructions` template.
6. The template greets the user by email address, states that the account was locked due to too many failed sign-in attempts, and renders a one-time unlock link.
7. The email is delivered to the user's address with click tracking disabled.

### Subforem context cannot be resolved (database unavailable)

1. During `setup_subforem_context`, a database error (`ActiveRecord::StatementInvalid` or `ActiveRecord::NoDatabaseError`) is raised.
2. The error is rescued; `@subforem_id` is set to `nil` and `@subforem_domain` falls back to `Settings::General.app_domain` or `ApplicationConfig["APP_DOMAIN"]`.
3. The email is still sent with the fallback domain used to construct the unlock URL.

## Failures / Exceptions

- If the subforems table does not exist, `determine_subforem_id` returns `nil` and the system uses the default community domain for the unlock URL.
- If `Settings::General.app_domain` raises a database error, the system falls back to `ApplicationConfig["APP_DOMAIN"]` as the ultimate host fallback.
- Click tracking is always suppressed for this mailer; the `save_ahoy_options` override applies to all actions in `DeviseMailer`, including `unlock_instructions`.
