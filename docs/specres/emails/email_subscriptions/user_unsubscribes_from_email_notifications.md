## Functional Overview

When a user clicks an unsubscribe link in an email, the system verifies a signed token embedded in the URL query parameter `ut`. If the token is valid and not expired, the system turns off the corresponding email notification setting for the user and renders a confirmation page identifying the unsubscribed email type by a human-readable name. If the token has expired, the system renders an invalid-token error page. If the token signature is invalid or missing, the system responds with a 404 not-found error.

## Design Intent

Token-based unsubscribe links are generated by the mailer using Rails' `MessageVerifier` with a 31-day expiration window. This avoids requiring the user to be authenticated while still preventing third-party tampering with the unsubscribe request. The `preferred_email_name` hash maps internal notification setting keys to localized, human-readable descriptions shown on the confirmation page.

## Key Members

- `ut` (query parameter) — signed, base64-encoded token containing `user_id`, `email_type`, and `expires_at`
- `email_type` — symbol key corresponding to a boolean attribute on `NotificationSetting` (e.g., `email_mention_notifications`)
- `@email_type` — human-readable label assigned to the instance variable for rendering on the confirmation page

## Scenarios

### Successful unsubscribe with valid token

1. The user visits the unsubscribe URL with a valid `ut` token in the query string.
2. The system verifies the token signature using the Rails message verifier.
3. The system checks that the token has not expired.
4. The system finds the user identified in the token and sets the relevant email notification setting to false.
5. The system renders the unsubscribe confirmation page, displaying a human-readable name for the email type that was disabled.

### Token is expired

1. The user visits the unsubscribe URL with a token whose `expires_at` time is in the past.
2. The system verifies the token signature successfully.
3. The system detects that the token has expired and renders the `invalid_token` page instead of unsubscribing the user.

### Token signature is invalid or missing

1. The user visits the unsubscribe URL with a malformed, tampered, or absent `ut` parameter.
2. The `MessageVerifier` raises `ActiveSupport::MessageVerifier::InvalidSignature`.
3. The system responds with a 404 not-found error.

## Failures / Exceptions

- `ActiveSupport::MessageVerifier::InvalidSignature` — raised when the `ut` parameter is missing, malformed, or tampered with; caught and converted to a 404 response via `not_found`.
- Expired token — when `expires_at` is in the past, the system renders the `invalid_token` template rather than modifying any user settings.
